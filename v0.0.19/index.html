LineageCollapse

Documentation for LineageCollapse, a Julia package for collapsing lineages in AIRR data.

Overview

LineageCollapse provides tools for processing and analyzing adaptive immune receptor repertoire (AIRR) data. It offers functions for data loading, preprocessing, lineage assignment, and lineage collapsing.

Architecture

Processing Pipeline

The library follows a linear pipeline where each stage transforms your data:

┌─────────────────────────────────────────────────────────────────────────────┐
│                          LineageCollapse Pipeline                           │
└─────────────────────────────────────────────────────────────────────────────┘

   AIRR TSV File
        │
        ▼
┌───────────────┐
│  load_data()  │  Load and validate AIRR-formatted data
└───────┬───────┘
        │ DataFrame
        ▼
┌──────────────────────┐
│  preprocess_data()   │  Filter, derive D-region, normalize columns
└──────────┬───────────┘
           │ DataFrame + d_region, v_call_first, j_call_first
           ▼
┌────────────────────────────────────────────────────────────────────────────┐
│  process_lineages(df, threshold)                                           │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │  For each (V-gene, J-gene, CDR3-length) group:                       │  │
│  │    1. Compute pairwise CDR3 distances (AbstractDistanceMetric)       │  │
│  │    2. Cluster sequences (ClusteringMethod)                           │  │
│  │    3. Assign lineage_id to each cluster                              │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
└──────────┬─────────────────────────────────────────────────────────────────┘
           │ DataFrame + lineage_id, cluster, cluster_size, relative_to_max_cdr3
           ▼
┌────────────────────────────────────────────────────────────────────────────┐
│  collapse_lineages(df, strategy)                                           │
│  ┌──────────────────────────────────────────────────────────────────────┐  │
│  │  CollapseStrategy determines output:                                 │  │
│  │    • Hardest() → one representative from max-frequency clones          │  │
│  │    • IgDiscover() → IgDiscover clonotypes representative               │  │
│  │    • Soft(cutoff) → all clones above frequency threshold                  │  │
│  │                                                                      │  │
│  │  AbstractTieBreaker resolves ties when selecting representatives     │  │
│  └──────────────────────────────────────────────────────────────────────┘  │
└──────────┬─────────────────────────────────────────────────────────────────┘
           │
           ▼
   Collapsed DataFrame (representatives or filtered clones)

Extension Points

You can extend the library by defining new types and methods:

Custom Distance Metric:

struct MyDistance <: AbstractDistanceMetric end

# Implement the required method
LineageCollapse.compute_distance(::MyDistance, x::LongDNA{4}, y::LongDNA{4}) = ...

Custom Tie-Breaker:

struct MyTieBreaker <: AbstractTieBreaker end

# Or use the built-in TieBreaker with custom criteria
my_breaker = TieBreaker([:my_column => true, :cdr3 => false])

Key Concepts

ConceptDescription
LineageGroup of sequences sharing V-gene, J-gene, CDR3 length, and similar CDR3
CloneUnique combination of D-region + lineage + V + J + CDR3 within a lineage
Clone FrequencyProportion of sequences in a lineage belonging to a clone
RepresentativeSelected sequence to represent an entire lineage

Built-in Tie-Breakers

FunctionStrategy
ByMostCommonVdjNt()Most common vdj_nt among maximum clone-frequency candidates
ByLineageMostCommonVdjNt()Most common vdj_nt by lineage-wide summed abundance (IgDiscover-style)
ByLowestVShm()Lowest V_SHM among all lineage members, then abundance, then vdj_nt
ByVdjCount()Among max-frequency candidates, highest per-clone vdj_count, then lexicographic cdr3
ByCdr3Count()Highest CDR3 count, then lexicographic CDR3
BySequenceCount()Highest sequence count, then lexicographic CDR3
ByMostNaive()Highest V/J identity (closest to germline)
ByLexicographic()Lexicographically smallest CDR3 (permutation-invariant)
ByFirst()First candidate in current row order (order-dependent)

Hardest() vs IgDiscover(): Hardest() first restricts to clones with maximum clone frequency (row fraction in the lineage), then applies the tie-breaker. ByMostCommonVdjNt() therefore cannot pick a minority clone. IgDiscover() matches IgDiscover's representative(): for lineages of size ≤ 2 it returns the first row; otherwise it picks the first row whose vdj_nt has the largest lineage-wide summed count. IgDiscover uses V_SHM only for _mindiffrate columns, not for the clonotype representative; use ByLowestVShm() if you want least-mutated V as the representative.

Single linkage: default clustering puts two CDR3s in the same lineage if they are connected by a path of pairwise distances ≤ threshold, not only if every pair is within the threshold.

Count: collapse_lineages treats count as additive unless you pass abundance=:rows. Missing count is 1 (the row still exists). If count is consensus-level abundance, rename it in preprocessing instead of summing it.

Tie-breakers can be combined: ByVdjCount() + ByLexicographic()

using Pkg
Pkg.add("LineageCollapse")

Quick Start

using LineageCollapse

# Load and preprocess
df = load_data("airr_data.tsv.gz")
df = preprocess_data(df; min_d_region_length=3)

# Assign lineages (threshold: 1 mismatch or 0.1 = 10% of CDR3 length)
lineages = process_lineages(df, 1)

# Collapse options:
# Option A: One representative from the dominant clone
result = collapse_lineages(lineages, Hardest())

# Option B: IgDiscover clonotypes representative
# result = collapse_lineages(lineages, IgDiscover())

# Option C: Keep clones with frequency ≥ 20%
result = collapse_lineages(lineages, Soft(0.2))

# Option D: Custom tie-breaking
result = collapse_lineages(lineages, Hardest();
                           tie_breaker=ByMostNaive(),
                           tie_atol=0.01,
                           abundance=:count)

Column reference

Meaning and computation of columns added by each stage. The most important is count (optional input and main abundance output).

Count (most important)

Input (optional): An optional numeric column count (e.g. read or UMI count per sequence). If present, it is the abundance of that row; if absent, each row is treated as abundance 1. Missing values are treated as 0 when summing.

Output (Hardest only): The collapsed result includes a count column: for each lineage it is the sum of the input count over all sequences in that lineage (total lineage abundance). If the input had no count column, this equals the number of sequences in the lineage.

How it is used: ByMostCommonVdjNt() and ByVdjCount() use summed count when ranking vdj_nt choices (see Built-in Tie-Breakers above for how they differ). Clone frequency and the Soft strategy use the number of sequences (rows) per clone, not the sum of count.

Command-line interface

A standalone CLI (lineage-collapse) lives under cli/ in the source tree. It reads one TSV (or gzip-compressed TSV), applies optional column filters, runs the same preprocessing and lineage pipeline as the Julia API, and writes collapsed output.

Build a binary (from a clone of the repository):

julia --project=cli cli/build.jl --force

The app is created under build/lineage-collapse/; the executable is build/lineage-collapse/bin/lineage-collapse.

Threads: set JULIA_NUM_THREADS (e.g. auto) before launching the binary so process_lineages can use multiple threads.

Run without building (same arguments as the binary):

julia --project=cli -e 'using LineageCollapseCLI; LineageCollapseCLI.main(ARGS)' -- path/to/input.tsv.gz -o out.tsv

Reference and examples: every flag, defaults, example data paths, and usage patterns are documented in cli/README.md in the repository.

Linux binary: each published GitHub Release can include a prebuilt lineage-collapse app tarball built by .github/workflows/Release-cli.yml (Linux x86_64). Download the asset from the release page, unpack, and run bin/lineage-collapse.

Regression driver for CLI options (pass any AIRR-style TSV or .gz):

julia --project=cli cli/test_options_smoke.jl path/to/example.tsv.gz

LineageCollapse.Hardest — Type
Hardest <: CollapseStrategy

Collapse strategy that selects exactly one representative per lineage from the clone(s) with maximum clone frequency, then applies tie_breaker to those candidates.

Lineage-wide policies (ByLineageMostCommonVdjNt, ByLowestVShm) ignore the frequency filter and select from every member of the lineage.

LineageCollapse.IgDiscover — Type
IgDiscover <: CollapseStrategy

One representative per lineage using IgDiscover's clonotypes.representative():

  1. If the lineage has ≤ 2 rows, take the first row (input-order dependent).
  2. Otherwise, take the first row whose vdj_nt has the largest lineage-wide summed abundance.

Clustering should use Hamming distance, threshold 1, and single linkage to match IgDiscover's CDR3 grouping. Single linkage means sequences can share a lineage through a chain of pairwise distances ≤ threshold even if some pairs exceed it.

source
LineageCollapse.LevenshteinDistance — Type
LevenshteinDistance <: AbstractDistanceMetric

Levenshtein (edit) distance metric.

process_lineages groups by exact CDR3 length before clustering, so sequences of different lengths are never compared. Levenshtein can still differ from Hamming for equal-length strings (shifts/indels), but it cannot join CDR3s that differ in length.

source
LineageCollapse.LineageMostCommonVdjNtTieBreaker — Type
LineageMostCommonVdjNtTieBreaker

IgDiscover-style representative: sum abundance for each vdj_nt across all rows in the lineage, take the vdj_nt with the largest total, return the first row that carries it.

If small_lineage_first_row is true (IgDiscover's representative()), lineages with one or two rows skip the abundance calculation and return the first row in input order.

source
LineageCollapse.LowestVShmTieBreaker — Type
LowestVShmTieBreaker

Select the row with the lowest V_SHM (least-mutated V) among all lineage members. Ties: higher abundance, then lexicographically smaller vdj_nt, then smaller cdr3. Missing V_SHM is treated as worst (largest).

source
LineageCollapse.MostCommonVdjNtTieBreaker — Type
MostCommonVdjNtTieBreaker

Among the candidate rows already selected by Hardest() (maximum clone frequency), pick the vdj_nt with the largest summed abundance, then a deterministic secondary key.

This is not IgDiscover's representative rule. IgDiscover sums vdj_nt over the entire lineage and, for lineages of size ≤ 2, returns the first row. Use ByLineageMostCommonVdjNt() or IgDiscover() for that behaviour.

LineageCollapse.ByMostCommonVdjNt — Method
ByMostCommonVdjNt()

Among maximum clone-frequency candidates, choose the vdj_nt with the highest summed abundance, then the lexicographically smallest vdj_nt. Requires vdj_nt.

This operates only on Hardest() candidates. For lineage-wide IgDiscover-style selection use ByLineageMostCommonVdjNt() or collapse_lineages(df, IgDiscover()).

LineageCollapse.ByVdjCount — Method
ByVdjCount()

Tie-breaker for Hardest() when several clones share the same top clone frequency: among those candidate rows only, prefer the larger vdj_count (then lexicographically smaller cdr3).

Here vdj_count is computed per clone (lineage_id, d_region, j_call_first, v_call_first, cdr3): within that clone, group rows by vdj_nt, sum abundance, and take the maximum of those per-vdj_nt sums. That single number is the clone's vdj_count score for every row in the clone.

Contrast with ByLineageMostCommonVdjNt(), which sums vdj_nt across the entire lineage.

LineageCollapse.collapse_lineages — Function
collapse_lineages(df::DataFrame, strategy=Hardest(); tie_breaker, tie_atol, abundance) -> DataFrame

Collapse lineages to representative sequences.

Arguments

  • df::DataFrame: Data from process_lineages with lineage_id column
  • strategy::CollapseStrategy=Hardest(): Collapse strategy
    • Hardest(): One representative per lineage (highest clone frequency, then tie_breaker)
    • IgDiscover(): IgDiscover clonotypes representative (lineage-wide most common vdj_nt)
    • Soft(cutoff): Keep all clones with frequency ≥ cutoff

Keyword Arguments

  • tie_breaker::AbstractTieBreaker: Strategy for breaking ties. Default depends on strategy.
  • tie_atol::Real=0.0: Tolerance for frequency comparison (Hardest only)
  • abundance::Symbol=:count: How to interpret abundance.
    • :count — use the count column when present (missing treated as 1); otherwise each row is 1. Values are treated as additive across lineage members (read/UMI/observation counts).
    • :rows — ignore count; each row contributes 1.

Clone frequency used by Hardest/Soft is the fraction of rows in a clone, not the sum of count.

Returns

For Hardest() and IgDiscover():

  • Selected rows with added count::Int (sum of abundances) and nVDJ_nt::Int (unique VDJ sequences)

For Soft(cutoff):

  • Rows meeting threshold with added clone_frequency::Float64 and sequence_count::Int

LineageCollapse.preprocess_data — Method
preprocess_data(df::DataFrame; min_d_region_length=nothing, deduplicate=false, use_barcode=false, rename_count_to_consensus_reads=false)::DataFrame

Preprocess the input DataFrame by performing data cleaning and transformation.

Arguments

  • df::DataFrame: Input DataFrame.
  • min_d_region_length::Union{Int,Nothing}=nothing: Inclusive minimum D-region length. Rows with length(d_region) < min_d_region_length are dropped. If nothing, no D-length filter.
  • deduplicate::Bool=false: Whether to deduplicate the DataFrame.
  • use_barcode::Bool=false: Whether to use barcode for deduplication (only applicable if deduplicate is true).
  • rename_count_to_consensus_reads::Bool=false: If true, renames :count to :consensus_reads before downstream steps. Use this when :count holds PCR- or consensus-level abundances that must not be summed like per-sequence read counts during lineage collapse.

If the input has a :count column with any value greater than 1 and rename_count_to_consensus_reads is false, a warning is emitted: lineage collapse aggregates :count across members, which can undo PCR bias correction if :count was already consensus-level abundance.

Rows with an explicit stop_codon == true are dropped. Missing stop_codon is treated as not having a stop codon (the row is kept). Rows with missing cdr3, v_call, or j_call are dropped. Invalid V/J coordinates yield missing D-region or vdj_nt and those rows are dropped.

An empty input yields an empty DataFrame with the derived columns present.

LineageCollapse.process_lineages — Method
process_lineages(df::DataFrame, threshold; linkage=:single) -> DataFrame

Process sequences into lineages using CDR3 clustering.

Sequences are grouped by v_call_first, j_call_first, and cdr3_length. Within each group, CDR3s are clustered. The default single linkage puts A and C in the same lineage whenever there is a chain A—B—C of pairwise distances ≤ threshold, even if A and C themselves exceed the threshold. Use :complete if every pair must be within the threshold.

Arguments

  • df::DataFrame: Preprocessed data with columns v_call_first, j_call_first, cdr3, cdr3_length, d_region
  • threshold: Clustering threshold. Integer for absolute mismatches, Float (0.0-1.0) for fraction of CDR3 length.
  • linkage::Symbol=:single: Hierarchical clustering linkage (:single, :complete, :average)

Returns

DataFrame with added columns:

  • lineage_id::Int: Unique lineage identifier
  • cluster::Int: Cluster assignment within V/J group
  • cluster_size::Int: Number of sequences in cluster
  • min_distance::Float32: Minimum distance to other CDR3s in cluster
  • cdr3_count::Int: Count of this CDR3 in cluster
  • max_cdr3_count::Int: Maximum CDR3 count in cluster
  • relative_to_max_cdr3::Float64: cdr3_count / max_cdr3_count (not a conventional frequency)
